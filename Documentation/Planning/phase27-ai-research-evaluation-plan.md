## 1. Objective and scope

Establish a reproducible, privacy-aware evidence base for VerifiaAI's Document Agent, Knowledge/RAG subsystem, Supervisor orchestration, and supported model adapters. Measure current behavior on versioned cases before selecting or changing models, prompts, retrieval settings, or agent behavior. Use the results to prioritize future improvements and demonstrate whether each change improves the same task without weakening authorization, human review, or deterministic business rules.

This phase follows the existing Phase 25 Final Documentation and Phase 26 Final Demonstration entries. Those deliverables remain open and are not replaced by Phase 27. Work on synthetic evaluation preparation can proceed without business-document approval. Evaluation with representative business documents remains blocked until the relevant Phase 20 and Phase 23 approvals are recorded.

**In scope:** data and provenance readiness; Document Agent and adapter assessment; RAG use-case definition, retrieval evaluation and integration decision; Supervisor quality evaluation; local and hosted model readiness; cross-component baselines; evidence-driven experiment planning; safe evaluation traceability.

**Out of scope for this documentation update:** all application behavior changes; new or modified tests, benchmark code, evaluation scripts, datasets, model settings, dependencies, migrations, CI, or deployment configuration; model downloads; live provider calls; costly experiments; transmitting business documents; guessing acceptance thresholds; and claiming results that were not freshly measured. Future implementation may change code only after a later authorized implementation task approves it.

Inspected the current branch/commit/remote reference and working tree; roadmap, checklist, root README, Documentation index and progress report; Phase 17 and Phase 23 plans; provider review and architecture documentation; Document Agent, parsing/intelligence/processing, KnowledgeService/chunker/embedding adapters, Supervisor and agent orchestration, model gateway/providers, and the related tests and evaluation assets.

### Priority rationale

- **P0** applies to owner prerequisites that block trustworthy acceptance or safe representative-data evaluation: the missing Phase 17 threshold decision and provider/data approval. Synthetic-only work can proceed while those decisions are pending.

- **P2** improves traceability and adversarial coverage after the foundational dataset and baseline procedures are established.
- **P3** is reserved for exploratory candidates (for example, hybrid retrieval or reranking) that should be attempted only if measured errors justify them.

## 7. Data, privacy, model, and threshold decisions

- Default to the versioned synthetic benchmark. The Phase 23 plan recorded authorization for bounded synthetic-only provider calls; this audit made no calls and did not recheck current credentials.
- Do not send real case data, customer documents, extracted text, financial identifiers, or confidential business information to a hosted model or embedding endpoint without explicit route/data approval and tested minimization. Follow [the provider review register](external-model-provider-review.md) and Phase 20 P20-OFFICIAL-022.
- Do not infer a Phase 17 threshold from the old score reports. The project owner must restore the original or approve a new versioned criterion before that gate is authoritative again.
- Do not treat mocked HTTP adapters or fake model outputs as provider compatibility, model quality, or route-selection evidence.
- No model/library ranking, current external benchmark claim, or license/commercial-use conclusion is made in this documentation audit. Future model assessment must record exact model/version and its applicable license evidence.

## 8. Definition of done

Phase 27 may be marked complete only when:

1. The document, RAG, Supervisor, dataset, model-readiness, and baseline tasks have dated evidence and explicit limitations.
2. Dataset provenance, version, labels, splits, and clean-checkout reproduction are independently validated.
3. Retrieval quality is measured separately from generated-answer quality; RAG integration is either demonstrated through authorized boundaries or explicitly retained as standalone retrieval.
4. Supervisor quality measurements are distinct from deterministic runtime/safety test passes and use the existing Phase 23 ownership for per-model/system acceptance.
5. Route/model changes are supported by comparable per-agent evidence; system-level evidence remains separate; costs are recorded only from dated verified rates and provider usage.
6. The missing Phase 17 threshold disposition is owner-approved without rewriting historical reports or fabricating values.
7. Representative-data results have the required provenance, license/authorization, provider approval, and tested minimization; otherwise they remain explicitly BLOCKED.
8. Security, privacy, authorization, human-review, deterministic rules, and workflow authority are preserved.
9. Only measured improvements are retained; failed or neutral experiments and their denominators are recorded.
10. Roadmap, checklist, progress report, README, and plan agree on phase/task status and evidence.
